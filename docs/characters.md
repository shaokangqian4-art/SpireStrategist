# 角色策略与新增角色清单

## 铁甲战士

复用现有 `Policy`、`IroncladSynergies` 和卡牌模型。消耗既可成体系，也可用于处理状态/诅咒；不要要求先有消耗流才接受有效处理牌。力量多段、格挡成长和易伤配合必须有实际支持。痛击不是高质量升级的默认首选，先古替换版本单独建模。主宰等第二张的价值有配套条件，不按统一重复惩罚处理所有能力牌。

历史用户偏好如捏奥剪刀/羊毛卷、飞鞋按路线、新叶/药膏按实际变牌结果，已经在相关策略内演化；扩展时读取 `NeowPolicy` 当前实现，不直接恢复早期聊天中的固定排行榜。

## 故障机器人：正式支持，阶段结档

当前模型版本 `defect-draft-0.14`。不再用“实验角色”标注；保留有限预测和未建模内容的具体说明。结档是结束集中开发阶段，不是宣称没有缺陷。

- 区分爪击增长、适应打击复制、黑球蓄积/激发、电球放大、玻璃/冰霜和状态输出。零散第一张组件不是硬锁体系；有配套的输出主线才需要更强的冲突约束。
- 物理与球伤害投资常冲突，但冰霜防守可共用；状态体系也能辅助其他主线，需评估处理状态能力。
- 不能只抓供能、过牌、烧牌而回避输出核心；核心是否可启动、成长是否足以应对 Boss，分别建模。不能临近三幕用互不配合的过渡攻击拼凑“已成型”。
- 暴涨的失球位代价对黑球蓄积特别大；其他球被挤出会激发，不能统一当球机制完全失效。核心是原生机制，不是流派名标签。
- 全息影像两张未敲可作为两次消耗回收；单张、需要持续回收或复制循环时仍重视升级。压缩第二张仅在状态负担足够高时再考虑，不做绝对禁止。
- 冷静头脑未敲的早期即时战力和敲后的净过牌分开。球系不自动高估循环；黑球不需要无配套雷霆。
- 核心多且依赖升级时重视火堆，但回血仍受未来安全约束，不把玩家成功赌敲的一局推广成固定低血不睡。

## 静默猎手：机制模型与全局接管

2026-11-01，本地 0.6.50 / `silent-draft-0.2`。86 张基础/先古/单人牌沿用首版机制参数，5 张多人牌忽略；新增本角色删除、升级、战力、遗物、无色牌特征和条件前瞻。已接入共用路线、商店、事件、先古、营火与单人循环执行。详见 [猎人模型与复现](silent-model.md)。不把接管可用当成胜率已验证。

- 小刀与毒是主要伤害方向，通常不另起第二套输出组件。涂毒可在刀组直接获益，但不能因此自动跨抓毒套件。第一张普通过渡不硬锁主线。
- 弃牌/奇巧、过牌、能量、保留、防守作为辅助层；有原生机制可独立出伤的群蛇、速行者、死神降临等仍评估真实启动条件。
- 已有遗物必须参与联动：三次攻击遗物不能误算三次技能；铜钹/结实绷带需要主动弃牌；异蛇头骨需要实际施毒入口；背包等共用遗物复用通用值。
- 删牌/变牌必须扣除失去现有输出引擎的代价；升级独立判断当前收益，不把所有升级差异塞入固定卡牌强弱排名。
- 辉眼按互斥路径、单次奖励选一张、商店实际价格和剩余预算搜索；预计牌不提前用于战损或当前战力。到达后重算。

## 储君与亡灵契约师：首版全局接管

0.6.53，分别采用 `regent-draft-0.1` / `necrobinder-draft-0.1`。每角色 86 个显式模型、5 个多人牌忽略；已接入原生奖励、营火、商店、事件、遗物选择、路线、辉眼、求解器交接和循环控制。详见[机制、统计来源与复现](regent-necrobinder-model.md)。不得把隔离构造用例计入胜率。

- 储君的星星、铸剑、生成和技能链分别评估资源、输出、启动和兑现；零能量的星费牌不是免费牌。
- 亡灵契约师区分奥斯提、灾厄、灵魂和虚无链；桥接组件可以兼容。玩家力量不增加奥斯提伤害，召唤不当玩家回血。
- 全角色继承共用捏奥偏好、药水预算、推荐标记、日志、语言、多人与中止规则，不复制角色专用界面。

## 新角色接入顺序

1. 提取当前原生卡牌、动态变量、升级差异、专属遗物与资源机制；确认实际类名，不靠中文简称猜机制。
2. 建立角色自己的卡牌功能/输出链、初始牌价值、长战成长与战损基线；禁止直接套战士力量/消耗模型。
3. 先开放只读建议与完整日志，再开放原生动作接管，最后开放循环。各阶段准确显示能力范围。
4. 接入所有供牌来源：奖励、商店、事件、先古、变化、复制；加牌、保留、删牌、升级、附魔分别比较。
5. 复用共用 UI、药水、商店预算、事件执行、日志、语言及安全门。角色差异放在策略，不复制一套界面代码。
6. 角色专属药水、遗物、先古与资源若不适用需明确降值/未建模；多人专属牌保持忽略。
7. 为新角色加入实际原生界面测试矩阵，并回归已有角色；尤其商店卡牌/遗物/药水/删牌、营火/先古/升级、多选和显示开关。
8. 记录真实试玩中每次候选、推荐、实际选择、玩家异议和结局；按失败链定位原因，保留独立验证种子。不要一次大改所有稀有度或重复叠加同一反馈。
9. 更新角色选择、默认配置、支持门、语言、manifest、Steam 描述与这里的状态；不得仅更改“暂不可用”字样。

未来值得做但尚未实现为通用接口：将 `DefectStrategy.Supported` 等历史命名的角色分派统一为角色能力注册表。改名和重构需单独验证，不在发布修复中顺便改遍整套接管流程。
